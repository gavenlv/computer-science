# 计算机科学学习体系 · 课程框架 v1

> 目标：让一个高中生或零基础大学生，沿着一条有先修关系、有实验、有项目、有论文训练的路径，
> 从「计算机是什么」走到「能独立做硕士级研究或专家级工程」。
>
> 本文档是**框架**，不是最终内容。它回答五个问题：给谁学、学什么、按什么顺序学、
> 每一课长什么样、网站如何承载。具体课时正文、动画与代码实验在后续阶段生产。

![计算机科学学习体系课程地图](assets/curriculum-map.png)

## 一句话结论

现在的站点有 5 个板块、75 个模块、471 条**课时大纲**，但缺少三样东西：

1. **完整的学科版图**：数学、计算理论、编译、分布式、安全、云计算、大数据、网络通信深度等尚未成为独立课程；
2. **从大纲到一节课的落差**：没有正文、图、交互、实验、练习和项目，学习者无法真正学会；
3. **从入门到研究级的阶梯**：没有先修图、没有能力标准、没有硕士级论文训练。

新框架把内容重组成 **「核心学院 + 10 个专业方向 + 研究训练」**，
用 **6 阶能力模型** 和 **知识图谱** 串起来，并为每一课定义了统一的内容标准。

## 框架规模

| 维度 | 现有 | 新框架目标 |
| --- | ---: | ---: |
| 学院 / 方向 | 5 个混合板块 | 1 个核心学院 + 10 个专业方向 |
| 课程 | 约 5 门（按板块折算） | 23 门核心课 + 63 门方向课 = **86 门** |
| 模块 | 75 | 约 **600 个** |
| 课时 | 471 条大纲 | 约 **3,000 个**完整课时 |
| 单条学习路径 | 无明确路径 | 核心 + 1 个方向 + 研究 ≈ **1,500–1,800 小时** |
| 交互 / 实验 | 0 | 每课至少 1 个可视化或交互，每模块至少 1 个实验 |
| 项目 | 0 | 6 级项目线 + 方向 Capstone + 研究项目 |
| 测评 | 仅「完成」勾选 | 诊断、课中检查、课后练习、模块测验、阶段考试、项目 Rubric |

> 「3,000 课时」是全站课程库的规模，不是要求一个人全部学完。
> 一个学习者完成「核心 + 一个方向 + 研究训练」约 1,500–1,800 小时：
> 按每周 10–15 小时，约 2–3 年；全职投入约 1–1.5 年。

## 五个关键设计决定

### 1. 先核心，后方向；方向不是「兴趣列表」，而是有入口条件的专精路径

核心学院解决「所有计算机人都必须会」的问题：编程、数学、算法、组成、操作系统、网络、数据库、
分布式、编译、理论、安全、软件工程。方向解决「在某个领域达到硕士/专家水平」的问题。
方向课默认要求核心课先修，避免「学 AI 却不懂矩阵和系统」的碎片化。

### 2. 六个能力阶，项目不是独立阶段

`L0 启程 → L1 入门 → L2 核心 → L3 专精 → L4 专家 → L5 研究`。
项目是每一阶的**证据**，而不是「学完所有知识后再做项目」的最后一站。
每一阶都有明确的出口能力、必须完成的实验/项目和可验收的测评。

### 3. 每一课都走「问题 → 直觉 → 机制 → 形式化 → 实验 → 应用 → 测评」

不是「先定义，再举例」，而是先让学习者看见一个真实问题，产生预测，再拆开机制。
图文并茂不是配图，而是让图承担解释任务；交互不是点缀，而是让学习者操纵变量、观察结果。

### 4. 知识图谱驱动，而不是线性目录

课程、模块、课时、知识点、先修关系、应用场景都是图上的节点与边。
首页可以按「我是谁 / 我想成为谁 / 我学过什么」生成路径，而不是只给一个固定顺序。

### 5. 「硕士毕业水平」用能力证据定义，不用营销话术

方向 L5 的出口不是「看完多少课」，而是：

- 能读懂该方向 3–5 篇顶会论文，并复现其中一篇；
- 能提出一个可验证的问题，完成 baseline、消融和评测；
- 能写出 15–30 页技术报告，并通过同行评审式答辩；
- 能说清该方向未来 3–5 年的开放问题。

这不等同于真实学位，但可以作为「能力等效」的学习标准。
