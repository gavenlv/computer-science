# 09 · 核心优先执行计划（3–4 人加速版）

> **注意**：本文是 3–4 人 + AI 的加速版，用于说明「有团队时怎样排」。
> **当前决策是 1 人，单人主排期请以 [11 单人执行策略](11-solo-strategy.md) 为准。**
> 单人第一年目标 100–130 课时；本文的 230 课时/6 个月不适用于单人。
>
> 依据 [00 · 已锁定决策](00-decisions.md)：
> **10 个方向全做，但先完成计算机基础（Core v1 → Core v2），网络作为第一旗舰。**
>
> 本文回答：有 3–4 人时先做什么、做多少、多长时间、怎样算完成。

---

## 1. 目标与验收定义

### 1.1 「先完成计算机基础」的准确含义

不是「4 门基础课」，而是核心学院 **23 门 / 165 模块 / 811 课时**，分两批：

| 批次 | 课程 | 课时 | 目标 |
| --- | ---: | ---: | --- |
| **Core v1** | 15 门 | 555 | 零基础 → 能写、懂数学、懂系统、能抓包、能建库、能做小项目 |
| **Core v2** | 8 门 | 256 | 补全算法 II、微积分、分布式、编译、理论、安全、系统设计、写作 |
| **合计** | 23 门 | 811 | 完整计算机基础 |

> Core v1 完成前，**不全面推进其余 9 个方向**。
> 例外：网络旗舰的 S03/N01/N03 可提前，因为 S03 本身就是核心课。

### 1.2 「完成」不是「有目录」

每门课达到以下标准才算完成：

- [ ] 所有课时有正文、图/动画、实验、练习、解析；
- [ ] 每模块有 1 个可运行 Lab；
- [ ] 每门课有 1 个结课项目 + Rubric；
- [ ] 每门课有 1 套模块测验（≥ 80 分掌握）；
- [ ] 每门课有先修、出口能力、来源、审校记录；
- [ ] 5 名目标用户试学通过；
- [ ] 无 P0 事实/代码错误。

### 1.3 第一旗舰的验收

S03 计算机网络必须成为「内容标准样板」：

- 10 个模块 / 50 课时全部完成；
- 5 个可复用可视化/交互组件；
- 3 个真实实验：抓包、TCP 状态机、拥塞对比；
- 1 个 P2 项目：TCP 子集 + HTTP 服务器，或网络测量报告；
- 100 名 beta 学习者，首课完成率 ≥ 60%，前后测提升 ≥ 20%。

## 2. 建设顺序（Wave）

```
Wave 0  框架/标准/样板（4 周）
   ↓
Wave 1  启程 + 编程 + 算法 I + 网络旗舰（约 230 课时）
   ↓
Wave 2  组成 + OS + 离散数学 + 数据库（约 190 课时）
   ↓
Wave 3  线代 + 概率 + 软工 + C 系统（约 135 课时）
   ↓
Wave 4  Core v2（256 课时）
   ↓
Wave 5  网络方向 N01–N07（240 课时）
   ↓
Wave 6  AI 方向（290 课时）
   ↓
Wave 7  大数据 / 安全 / 云（720 课时）
   ↓
Wave 8  图形 / 嵌入式 / 架构 / HCI / 量子（606 课时）
```

### 2.1 Wave 明细

| Wave | 课程 | 课时 | 关键产出 | 退出标准 |
| --- | --- | ---: | --- | --- |
| 0 | 无 | 0 | 3 个 Storyboard、设计系统、迁移表、沙箱选型 | 评审通过；5 人试学 |
| 1 | F00–F03、C01、C03、S03 | 230 | 启程 100 + 算法 80 + 网络 50 | 100 beta；首课完成 ≥ 60% |
| 2 | S01、S02、M01、S04 | 190 | 组成 50 + OS 50 + 离散 40 + 数据库 50 | 4 个组件复用；掌握率 ≥ 70% |
| 3 | M02、M03、E01、C02 | 135 | 线代 30 + 概率 30 + 软工 40 + C 35 | Core v1 完成 |
| 4 | Core v2（C04/M04/S05–S08/E02/E03） | 256 | 算法 II、微积分、分布式、编译、理论、安全、系统设计、写作 | Core v1+v2 完整 |
| 5 | N01–N07 | 240 | TCP 实现、路由、测量、SDN、无线、CDN/QUIC、攻防 | 网络方向 Capstone |
| 6 | A01–A08 | 290 | ML、DL、CV、NLP、RL、生成、LLM、AI 系统 | AI 方向 Capstone + 论文复现 |
| 7 | B01–B07、SEC01–SEC07、K01–K07 | 720 | 数据、安全、云三方向 | 各 1 个 Capstone |
| 8 | G、EM、AR、H、Q | 870 | 图形、嵌入式、架构、HCI、量子 | 各 1 个 Capstone |

> 课时数为「课程表标准量」，实际生产会因拆课/合并浮动 ±15%。

## 3. 12 个月计划（小团队现实版）

假设：**3–4 人 + AI 辅助 + 外部学科审校**，每人每周投入 20–30 小时。
产能按 **30–40 课时/月**（团队合计）估算。

| 月份 | 重点 | 产出 | 里程碑 |
| --- | --- | ---: | --- |
| M0 | 决策/访谈/Storyboard/设计系统 | 0 课时 | Wave 0 完成 |
| M1 | F00 前 3 模块 + F01 前 3 模块 + S03 握手 | 25–30 | 私测 20 人 |
| M2 | F00 完成 + F01 完成 | 35–40 | 启程课可完整走通 |
| M3 | F02 + F03 + C01 前 2 模块 | 35–40 | 第一个 P0 作品 |
| M4 | C01 完成 + C03 前 3 模块 | 40 | 编程地基完成 |
| M5 | C03 完成 + S03 前 5 模块 | 40 | 网络旗舰前段 |
| M6 | S03 后 5 模块 + 复盘 | 30 | **Wave 1 完成（约 230 课时）** |
| M7 | S01 前 5 模块 | 25 | 组成原理可学 |
| M8 | S01 完成 + S02 前 3 模块 | 35 | CPU/缓存实验 |
| M9 | S02 完成 | 40 | OS 实验（调度/内存） |
| M10 | M01 离散数学 | 40 | 数学课上线 |
| M11 | S04 前 5 模块 | 25 | 数据库索引/事务 |
| M12 | S04 完成 + 年度复盘 | 25 | **Core v1 约 75%（约 420 课时）** |

> 这是「3–4 人 + AI」的乐观但可执行节奏（约 35–40 课时/月为上限）。
> **1–2 人 + AI**：产能约 8–18 课时/月，12 个月约 100–200 课时，Core v1 需要 3–6 年。
> **6–8 人团队**：产能约 40–60 课时/月，12 个月可完成 Core v1。

### 3.1 24–36 个月视图

| 时间 | 目标 | 累计课时 |
| --- | --- | ---: |
| 12 个月 | Core v1 约 75% | 420 |
| 18 个月 | Core v1 完成 | 555 |
| 24 个月 | Core v2 约 60% + 网络 N01/N03 | 775 |
| 30 个月 | Core v2 完成 + 网络 N01–N03 | 931 |
| 36 个月 | 网络方向完成 + AI 起步 | 1,131 |

> 10 个方向全量约 3,000 课时，3–4 人需要 8–10 年；6–8 人团队 5–7 年；1–2 人 15+ 年。
> 这是「完整课程库」的时间尺度，不是「一条路径」的时间尺度。

## 4. 前 90 天：具体到周

### Week 1–2：确认与访谈

- [ ] 确认 Core v1 边界（15 门 / 555 课时）；
- [ ] 访谈 6–8 名目标学习者（高中生 2、大学生 2、转行 2、研究生 1–2）；
- [ ] 记录：动机、时间、数学基础、放弃点、喜欢的学习形式；
- [ ] 输出《学习者画像 v1》。

### Week 3–4：Storyboard 与设计系统

- [ ] 3 个 Storyboard：
  - F01「循环：让程序替你重复」；
  - S01「缓存为什么快」；
  - S03「TCP 三次握手」。
- [ ] 视觉规范：颜色语义、字体、图类型、动画规范；
- [ ] 3 个组件原型：循环单步器、缓存模拟器、协议时序/抓包回放；
- [ ] 技术验证：浏览器内 Python/C 沙箱、SQL 沙箱、pcap 回放。

### Week 5–6：第一条垂直切片

- [ ] F01 前 4 课时完整生产（正文 + 图 + 实验 + 练习）；
- [ ] S03 握手课时完整生产（含 Wireshark 实验）；
- [ ] S01 缓存课时完整生产（含矩阵遍历性能实验）；
- [ ] 内容模板：课时/实验/题目/Rubric。

### Week 7–8：5 人试学

- [ ] 每节课 5 名目标用户，记录：
  - 在哪一段卡住；
  - 哪个图没看懂；
  - 哪个实验失败；
  - 测验错在哪；
  - 愿不愿意继续。
- [ ] 修订：至少 2 轮；
- [ ] 输出《单课可用性报告 v1》。

### Week 9–10：迁移表与首批内容

- [ ] 471 条旧大纲 → 新课程映射（keep/rewrite/discard/split）；
- [ ] 旧 URL/进度迁移方案；
- [ ] F00 前 3 模块 + F01 前 6 课时进入生产；
- [ ] 组件库 v0：3 个组件可复用。

### Week 11–12：私测与复盘

- [ ] 20 名私测用户；
- [ ] 埋点：课时完成、检查点、实验成功率、测验；
- [ ] 复盘：产能、质量、卡点；
- [ ] 制定下一个 12 周计划；
- [ ] 决策：是否加速（加人/外包/工具）。

## 5. 内容生产节奏（小团队）

### 5.1 每周节奏

| 天 | 任务 |
| --- | --- |
| 周一 | 选题/目标/Storyboard 评审 |
| 周二–周三 | 正文 + 代码 + 实验 |
| 周四 | 图/交互 + 题目 |
| 周五 | 审校 + 试学 + 发布 |
| 周末 | 数据复盘/下周排期 |

### 5.2 每课时产出包

- 正文（1,500–3,000 字）；
- 1 个主视觉 + 1–2 个辅助图；
- 1 个可运行实验 + 预期输出 + 排查；
- 3–5 道题 + 解析；
- 1 个失败案例；
- 1 个真实系统/论文链接；
- 来源与审校记录。

### 5.3 产能与质量取舍

| 模式 | 课时/月（3–4 人合计） | 质量 | 适用 |
| --- | ---: | --- | --- |
| 全定制（每课新动画） | 8–12 | 最高 | 旗舰课 |
| 模板 + 复用组件 | 30–40 | 高 | 核心课 |
| 纯文本 + 截图 | 40–50 | 中 | 先验证需求 |

> 旗舰课 S03 用「全定制」；普通核心课用「模板 + 复用组件」；先用「纯文本 + 截图」验证需求，再逐步升级。

## 6. 质量门禁（每门课）

### Gate 1：内容

- 一节课一个主角；
- 10 个块齐全；
- 图有解释任务；
- 实验可运行；
- 题目有解析/误区；
- 来源可核验。

### Gate 2：体验

- 移动端可读；
- 键盘可操作；
- 动画可暂停；
- 首屏 < 3s；
- 错误提示友好。

### Gate 3：学习效果

- 5 人试学；
- 前后测提升 ≥ 20%；
- 检查点正确率 ≥ 60%；
- 实验成功率 ≥ 70%；
- 90% 用户能说出「这节课解决了什么问题」。

### Gate 4：发布

- 学科/代码/语言/版权审校；
- 埋点齐全；
- 回滚方案；
- 30 天复审。

| 角色 | 1 人 | 2 人 | 3–4 人 |

| 学科主编 | 你 | 你 | 你 |

| 可视化 | 外包/模板 | 外包 | C |

| 试学 | 社群 | 社群 | 社群 |

> 3–4 人时，一人内容、一人教学/题目、一人可视化/前端，产能最高。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 核心 555 课时太大 | 先做 Wave 1（230 课时），用数据决定是否继续 |
| 网络旗舰成本高 | 5 个组件复用；先做 3 个实验，不做全定制动画 |
| 1 人产能不足 | 模板化 + AI 草稿 + 外部审校；目标 6–10 课时/月 |
| 数学课完课率低 | 先做「用得上」的数学，配代码/图；不追求证明技巧 |
| 实验环境复杂 | 浏览器优先；本地/容器提供一键脚本 |
| 内容过时 | 原理为主 + 一个代表实现；每 90 天复审 |
| 旧内容迁移出错 | 映射表 + 301 + 灰度 + 备份 |
| 过度承诺「硕士」 | 统一用「能力等效」；展示证据，不卖学位 |
