# 01 · 愿景、学习者与能力模型

## 1. 问题诊断：现在的站点「有目录，没有课程」

现有站点并不是没有内容：它有 5 个板块、75 个模块、471 条课时大纲，覆盖了编程、算法、
计算机基础与 AI。但把它当作学习产品看，存在四个结构性问题。

### 1.1 大纲不是课程

每条课时只有 3–5 个知识点短句，例如「TCP 三次握手」「虚拟内存」「Transformer 注意力」。
学习者看完仍然不知道：

- 这个概念为了解决什么问题而出现？
- 它在真实系统里长什么样？
- 我能不能自己跑一遍、改一改、看它坏掉？
- 我怎样知道自己真的学会了？

大纲适合做目录，不能替代正文、图、实验和练习。

### 1.2 板块混合了不同层级的东西

- 「编程语言基础」把 Python 入门、C 语言、JVM、编译器实现放在同一个板块；
- 「计算机基础四大件」把组成原理、操作系统、网络、数据库压缩成 16 个模块；
- 「方向进阶与项目实战」把前端、后端、数据、工程素养混在一起；
- 「AI 与新兴技术」其实是一个专业方向，却和基础课并列。

这会导致两个后果：**基础不够深，方向不够专**。一个想学网络的人，在「四大件」里只能分到
6–10 个课时；一个想学 AI 的人，没有系统学过线代、概率和系统工程。

### 1.3 缺少三块关键拼图

- **数学与理论**：离散数学、线性代数、概率统计、微积分、计算理论没有独立课程；
- **系统与工程深度**：编译、分布式、安全、性能工程、云原生没有形成完整课程链；
- **研究方向**：没有论文阅读、复现、写作与答辩训练，「专家级」缺少可验收的标准。

### 1.4 没有「路径」

现在的顺序是板块顺序，不是先修顺序。一个零基础学习者不知道：

- 学操作系统之前要不要先学 C？
- 学 AI 之前要不要先学概率？
- 想搞网络安全，应该先学网络还是先学密码学？
- 已经会 Python，能不能跳过哪些课？

没有先修图，就没有真正的个性化路径。

## 2. 目标与非目标

### 2.1 目标

**主目标**：构建一套从高中/大学零基础到「计算机核心全懂 + 一个方向达到硕士等效/专家工程」
的完整学习体系，并让每一课都具备图文、交互、实验、测评。

具体拆成五个可验收目标：

1. **完整性**：覆盖 CS2023 的 17 个知识领域中的核心部分，并延伸出 10 个专业方向；
2. **阶梯性**：6 个能力阶，每阶有先修、出口能力、项目和测评；
3. **可理解性**：高中生能读懂第一遍，大学生能做出第二遍，研究生能读出第三遍；
4. **可实践性**：每个模块至少一个可运行实验，每个方向至少一个 Capstone；
5. **可研究性**：每个方向有论文清单、复现任务和写作训练。

### 2.2 非目标

- **不是「科普站」**：不满足于「AI 是什么」「网络分几层」的泛泛介绍；
- **不是「工具教程站」**：不以教完某个框架/云厂商产品为目标，工具会过时，原理不会；
- **不是「面试刷题站」**：算法课会覆盖面试，但不以刷题数量为目标；
- **不是「速成班」**：不承诺 3 个月转行；完整路径是 1,500 小时量级；
- **不替代真实学位**：提供的是能力等效的学习路径与证据，不授予学位。

## 3. 学习者画像

### 3.1 四类主要用户

| 画像 | 起点 | 主要痛点 | 推荐入口 | 典型路径 |
| --- | --- | --- | --- | --- |
| **高中生小高** | 高一，数学在学，没写过代码 | 不知道计算机专业学什么；怕数学 | L0 启程 | L0 → L1 → L2 部分 → 高考后选方向 |
| **大学生小大** | 大二计算机，学过 Python 和数据结构 | 课程碎片化；系统课听不懂；不知道方向 | L1 诊断 → L2 核心 | 核心 → 1 个方向 → 项目/保研/求职 |
| **转行者小转** | 会一点 Python，做过脚本 | 缺系统基础；项目拿不出手 | 入学诊断 → 补 L1 | 核心压缩版 → 方向 → Capstone |
| **研究生/在职小研** | 有 CS 基础，想深入某个方向 | 缺论文训练；工程深度不够 | L3 方向诊断 | 方向 L3–L5 → 论文复现 → 研究项目 |

### 3.2 次要用户

- **高中信息技术教师**：需要一套可拆分进课堂的模块与实验；
- **企业导师/面试官**：需要能力标准与项目 Rubric；
- **家长**：需要看见阶段目标与时间投入，而不是「无限课程列表」。

### 3.3 入学诊断（Placement Test）

不做「一刀切从第一课开始」。每个入口提供 20–40 分钟诊断：

- **编程**：变量、循环、函数、数据结构、调试；
- **数学**：函数、集合、概率、矩阵、证明直觉；
- **系统**：进程/线程、内存、网络分层、SQL；
- **方向**：该方向的核心概念与代码阅读。

诊断结果输出「已掌握 / 建议补课 / 可直接进入」三档，并生成最短路径。
诊断本身也是学习内容：每道错题都链接到对应知识点。

## 4. 六阶能力模型

六个阶不是「难度标签」，而是**能力状态**。每一阶都必须有出口证据，不能靠「看完」升级。

| 阶 | 名称 | 核心问题 | 出口能力 | 必须交出的证据 | 建议时长 |
| --- | --- | --- | --- | --- | --- |
| **L0** | 启程 | 计算机如何运行？我能不能让它听我的话？ | 能解释程序从源代码到运行的完整链路；能写 50–150 行 Python 解决小问题；会用命令行、编辑器和 Git | 3 个小工具 + 概念测验 | 60–80h |
| **L1** | 入门 | 我能不能独立写出结构清晰的程序？ | 能写 300–500 行程序；掌握核心数据结构与复杂度；能用离散数学表达简单证明；能读英文文档 | 1 个 CLI/数据分析作品 + 笔试 | 200–280h |
| **L2** | 核心 | 计算机系统到底怎样工作？ | 能实现小型解释器/HTTP 服务器/存储引擎/OS 实验；能定位性能与并发问题；能设计关系模型 | 4 个核心 Lab + 综合考试 + 系统设计 | 450–600h |
| **L3** | 专精 | 这个方向的经典方法为什么有效？ | 能复现方向内 1–2 个经典系统/算法；能读懂该方向论文；能完成中型方向项目 | 方向项目 + 论文精读报告 | 250–350h |
| **L4** | 专家 | 怎样把方法做到生产级、极致性能与可靠？ | 能负责生产系统；能做架构取舍；能定位深水区问题；能带 2–3 人完成交付 | 生产级 Capstone + 性能/可靠性报告 + 代码评审 | 250–400h |
| **L5** | 研究 | 怎样提出新问题、验证新想法、写出可信结论？ | 能读顶会论文并复现；能提出可验证问题；能完成 baseline/消融/评测；能写论文级报告 | 论文复现 + 原创研究项目 + 答辩 | 300–500h |

### 4.1 为什么把「项目实战」从阶段里拿掉

现有模型把「项目实战」放在「高级」之后、「专家级」之前，暗示「先学完再做项目」。
这与真实学习相反：

- L0 就可以做「猜数字/记账本」，项目是理解的证据；
- L2 的 OS/DB/编译器 Lab 本身就是项目；
- L4/L5 的项目是生产级/研究级，不是「第一次做项目」。

新模型把项目拆成 **P0–P5 项目线**，与六个阶并行：

| 项目线 | 对应阶 | 项目形态 | 验收重点 |
| --- | --- | --- | --- |
| P0 微作品 | L0 | 小工具、小游戏、数据小报 | 能跑、能讲清 |
| P1 入门作品 | L1 | CLI 应用、数据分析、静态网站 | 结构、测试、文档 |
| P2 核心 Lab | L2 | mini OS / TCP 栈 / 存储引擎 / 编译器 | 正确性、边界、性能 |
| P3 方向项目 | L3 | 方向内经典系统复现 | 对标论文/开源实现 |
| P4 生产级 Capstone | L4 | 可上线、可压测、可观测的系统 | 可靠性、成本、运维 |
| P5 研究项目 | L5 | 论文复现 + 原创扩展 | 新颖性、实验设计、写作 |

### 4.2 每阶的「三遍法」

同一个主题在不同阶重复出现，但深度不同。以「TCP」为例：

- **L0（直觉）**：数据包像快递，为什么需要确认和重传？
- **L2（机制）**：三次握手、滑动窗口、拥塞控制、状态机，抓包验证；
- **L3（实现）**：自己实现 TCP receiver/sender，处理丢包、乱序、超时；
- **L4（生产）**：BBR、QUIC、CDN 边缘、千万级并发连接调优；
- **L5（研究）**：读拥塞控制论文，复现并改进一个算法。

这就是「从入门到专家」的正确打开方式：不是一次讲完，而是多次回来，每次都更深。

## 5. 「硕士毕业水平」如何定义

「硕士级」不能用一个课时数或一个证书来证明。我们把方向 L5 的出口拆成 **知识、能力、研究品味** 三个维度。

### 5.1 知识：研究生级课程覆盖

每个方向至少包含：

- 3–4 门方向核心课（本科高年级/研究生入门）；
- 2–3 门高级专题课（研究生级）；
- 1 门研究方法的课（论文阅读、实验设计、写作）。

知识验收不靠「看完」，而靠：

- 闭卷概念题（解释、比较、推导）；
- 开卷设计题（给定场景做取舍）；
- 代码阅读题（读懂一段真实系统代码）。

### 5.2 能力：能复现，也能扩展

- **复现**：从论文/规格出发，独立实现一个 baseline，结果与论文同量级；
- **扩展**：至少做一个消融或改进，解释为什么有效/无效；
- **工程**：代码可复现、有测试、有 benchmark、有 README；
- **表达**：15–30 页技术报告 + 20 分钟答辩，能回答「你为什么不用另一种方法」。

### 5.3 研究品味：知道什么是好问题

- 能画出该方向的知识树，指出 3–5 个开放问题；
- 能评价一篇论文的贡献、局限与实验设计；
- 能说清「这篇论文如果让我改，我会改哪里」。

### 5.4 与真实学位的差距

| 维度 | 本体系 | 真实硕士 |
| --- | --- | --- |
| 课程知识 | 可对标研究生课程 | 有学分与成绩单 |
| 研究训练 | 论文复现 + 原创项目 + 报告 | 导师指导、组会、开题/中期/答辩 |
| 同行评审 | 社区/导师评审（待建设） | 正式评审委员会 |
| 学位认证 | 无 | 有 |
| 时间投入 | 1,500–1,800h（单方向） | 2–3 年全日制（含课程、论文、导师） |

**结论**：本体系可以让你达到「能读研、能进研究型团队、能独立做方向项目」的能力，
但不能替代真实学位的认证与导师指导。网站应诚实表达这一点。

## 6. 设计原则

### 6.1 具体先行，形式随后

先给一个可感知的现象/故障/故事，再给定义与公式。
例：先看「0.1 + 0.2 ≠ 0.3」的崩溃，再讲 IEEE 754。

### 6.2 每课只承载一个核心概念

一节课可以有很多细节，但只能有一个「主角」。
如果一节课出现三个以上新核心概念，拆成多节。

### 6.3 图承担解释，不承担装饰

每张图必须能回答一个「为什么/怎么发生」的问题。
禁止「配一张无关的科技感插图」。

### 6.4 交互必须改变理解

交互不是「点一下有动画」，而是让学习者：

- 改一个参数，观察系统行为变化；
- 单步执行，看到状态迁移；
- 预测结果，再验证；
- 弄坏它，再修复。

### 6.5 先手写，再用库

核心概念必须至少手写一次最小实现：
手写哈希表、手写 TCP 状态机、手写 B+ 树、手写解释器。
之后再引入工业库，并解释库多做了什么。

### 6.6 从真实系统取证

讲网络就抓包，讲操作系统就 `strace`/`perf`，讲数据库就看执行计划，
讲安全就打靶场。真实系统的「脏细节」是最好的教材。

### 6.7 数学是工具，不是门槛

数学课独立成体系，但每个方向课都要「用得上」：
线代用于图形变换与 embeddings，概率用于评估与 A/B，离散数学用于算法与密码。

### 6.8 失败优先

先展示 bug、崩溃、攻击、性能退化，再讲正确做法。
失败案例比成功案例更能建立直觉。

### 6.9 间隔与检索

每课 3–5 个检查点，每模块一次测验，1/3/7/21 天复习队列。
不做「看完即完成」。

### 6.10 可迁移，而非可背诵

考试允许带「一页纸」；重点是解释、设计、调试，不是背 API。

## 7. 成功指标

### 7.1 学习效果

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 课前/课后增益 | 同一套概念题的前后测差值 | 平均 +30% 以上 |
| 模块掌握率 | 模块测验 ≥ 80 分的人数比例 | ≥ 70% |
| 项目完成率 | 开始项目后提交并通过 Rubric 的比例 | ≥ 50% |
| 7 日留存 | 首次学习后 7 天内再次学习 | ≥ 40% |
| 30 日留存 | 首次学习后 30 天内再次学习 | ≥ 25% |
| 迁移测试 | 新场景下应用知识的表现 | 显著高于纯记忆组 |

### 7.2 内容质量

- 每课必须有：1 个主视觉、1 个交互/实验、3 个检查点、1 个失败案例；
- 每模块必须有：1 个可运行 Lab、1 套练习、1 个项目里程碑；
- 每方向必须有：1 个 Capstone、3–5 篇论文、1 次答辩；
- 每门课必须有：先修、出口能力、Rubric、更新日期、参考来源。

### 7.3 产品指标

- 诊断完成率、路径完成率、课时完成率、实验运行成功率；
- 「继续学习」点击率、搜索成功率、术语跳转率；
- 移动端可用性、首屏性能、无障碍达标率。

## 8. 本框架的边界与待确认项

### 已确认（2026-10-25，详见 [00 决策](00-decisions.md)）

1. **方向数量**：10 个方向全做，不收敛；
2. **建设顺序**：先完成计算机基础（Core v1 → Core v2），再全面推进方向；
3. **第一旗舰课**：计算机网络；
4. **「硕士级」表述**：能力等效，不授学位；
5. **团队规模**：1 人 + AI 辅助 + 外部学科审校。

### 仍需确认

1. **分层内容（D-006）**：核心+网络+AI 原创、数据/安全/云精编、其余导读，是否接受？
2. **内容语言**：中文为主 + 英文术语，还是中英双语？
3. **是否做后端/账号**：MVP 用 localStorage，还是一开始就做账号/云同步？
4. **是否做认证/付费**：只做学习记录与作品集，还是做付费证书/班级？
5. **数学深度**：默认「计算机专业本科数学 + 方向所需研究生数学」，不追求数学系深度。
6. **AI 辅助边界**：默认 AI 用于草稿、题目变体、代码解释，但必须有人类学科审校与来源标注。
