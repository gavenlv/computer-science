## 3. 现有内容处置

### 3.1 处置原则

- **保留**：结构合理、主题属于新核心课的内容；
- **改写**：主题对，但层级/表述/深度不对；
- **拆分**：一个旧模块对应多门新课程；
- **合并**：多个旧模块重复/碎片化；
- **归档**：工具/语言过细、与核心无关、质量不足。

### 3.2 板块级处置

| 旧板块 | 处置 | 去向 |
| --- | --- | --- |
| `languages` | 拆分 + 改写 | F00/F01/F02、C01、C02；JS/Java/Go 等改为选修 `X` 课程 |
| `dsa` | 保留 + 改写 | C03/C04；竞赛专题改为选修/项目 |
| `fundamentals` | 拆分 + 加深 | F00、S01、S02、S03、S04、S05 |
| `engineering` | 拆分 + 重写 | E01、E02、E03；前端/全栈改为选修/项目；高并发/云原生转入 K/AR |
| `ai` | 保留 + 扩展 | A01–A08；补 CV/NLP/RL/生成模型/系统 |

### 3.3 课时级处置（预估）

| 处置 | 比例 | 说明 |
| --- | ---: | --- |
| 可直接复用为「课时种子」 | 35% | 标题 + 知识点方向正确，补正文/图/实验 |
| 需改写/重组 | 45% | 主题对但层级/顺序/深度不对 |
| 建议归档 | 20% | 过细的语言/工具内容、重复内容、与核心无关 |

> 471 条大纲中，约 165 条可作为「种子」，约 210 条需改写，约 96 条归档。
> 这不是精确统计，而是给内容排期的量级判断。

### 3.4 迁移风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 旧 URL 404 | 学习者流失/SEO 下降 | 301 + `aliases` + 灰度 |
| 进度丢失 | 信任受损 | 迁移脚本 + 旧 ID 映射 + 保留「旧完成」 |
| 内容重复 | 维护成本 | 先建映射表，再导入 |
| 审校瓶颈 | 进度慢 | 先做 3 门样板课，沉淀模板 |
| 旧内容质量差 | 拉低信任 | 标记 `legacy`，不直接发布 |

## 4. 建设策略：黄金路径 + 垂直切片

### 4.1 不做「横向铺 86 门课」

横向铺开会导致：

- 每门课都只有大纲，没有一节完整课；
- 学习者找不到一条能走通的路；
- 团队陷入「写目录」而不是「做课程」。

### 4.2 做「一条能走通的黄金路径」

**黄金路径 v1**：

```
F00 计算机如何思考
→ F01 Python 第一行代码
→ F02 开发者工具链
→ F03 数学预备
→ C01 程序设计进阶
→ C03 数据结构与算法 I
→ M01 离散数学
→ S01 计算机组成
→ S02 操作系统
→ S03 计算机网络
→ E01 软件工程
→ P2 核心 Lab（网络/OS 二选一）
→ 方向入口（网络通信优先）
```

这条路径覆盖「从零到能写、能懂系统、能做项目」，是最适合验证内容标准与产品体验的切片。

### 4.3 为什么第一门旗舰课选「计算机网络」

| 理由 | 说明 |
| --- | --- |
| 用户明确要求 | 「要知道底层通信原理，如何应用」 |
| 可视化强 | 数据包、状态机、时序图、拓扑、拥塞曲线 |
| 交互强 | 抓包回放、参数滑块、单步协议、路由模拟 |
| 可验证 | 每个实验都有真实输出（Wireshark/curl/ss） |
| 差异化 | 市面上「网络课」多，但「能抓包 + 能实现 + 能排障」的少 |
| 复用现有 | `fundamentals` 中的网络模块可作为种子 |

第二门方向旗舰课选 **AI**；OS/DB 作为核心阶段的系统样板课，不占用方向旗舰名额。

### 4.4 垂直切片的标准

每一门样板课必须完整走通：

```
课程目标 → 模块 → 课时 → 正文 → 图/动画 → 交互 → 实验 → 练习 → 测验 → 项目 → 埋点
```

只做「正文」不做「实验/测评」，不算切片完成。

### 7.2 产能估算

| --- | ---: | ---: | ---: |
| 1 人 + AI | 8–15 | 100–150 | 14–16 年（分层）/ 20+ 年（全原创） |
| 3–4 人 + AI | 30–40 | 360–480 | 8–10 年 |
| 6–8 人团队 | 40–60 | 400–600 | 5–7 年 |
| 15 人团队 | 40–60 | 400–600 | 4–6 年 |

> 这组数字不是劝退，而是让路线图诚实。**质量 × 规模 × 速度**三者只能选两个。
> 当前按 1 人执行，建议优先「质量 × 核心 + 网络」，再扩规模。

### 7.3 成本控制

- 模板化：课时模板、实验模板、题目模板、可视化组件复用；
- AI 辅助：草稿、变式题、代码解释、翻译；
- 外部审校：按课时付费的学科专家；
- 先做「可复用组件」，再做「一次性动画」；
- 用真实系统截图/录屏替代高成本 3D 动画。

## 8. 质量门禁

### 8.1 发布前（MUST）

- [ ] 学科审校：事实/公式/术语/来源；
- [ ] 代码审校：可运行、版本锁定、错误可复现；
- [ ] 语言审校：高中生可读、无歧义；
- [ ] 视觉审校：图有解释任务、Alt 文本、对比度；
- [ ] 无障碍：键盘、读屏、reduced motion；
- [ ] 版权：图/截图/论文引用有来源与许可；
- [ ] 5 名目标用户试学，记录卡点；
- [ ] 埋点：课时/检查点/实验/练习。

### 8.2 发布后（30 天）

- 完课率、检查点正确率、实验失败率；
- 错题分布、搜索失败词；
- 用户反馈/退课原因；
- 事实/代码问题 48 小时内修复。

### 8.3 复审（90 天）

- 内容是否过时（工具/论文/标准）；
- 题目是否太简单/太难（区分度）；
- 图/交互是否真的帮助理解（A/B/访谈）；
- 先修是否合理（学习路径数据）。
